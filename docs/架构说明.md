# 架构说明

## 目标

控制端和目标机都没有公网 IP，也不想维护一台中转 VPS。机器主人同意后，让独立运行的 Codex：

1. 在目标机上跑命令；
2. 看目标机屏幕、点击、打字；
3. 主人随时能看到、能撤销。

## 组件

| 组件 | 位置 | 来源 | 作用 |
|---|---|---|---|
| Tailscale | 两端 | 现成 | WireGuard 虚拟网，身份由 Tailscale 账号/tailnet 决定；打洞失败时经 DERP 中继，仍端到端加密 |
| OpenSSH | 两端 | 系统自带 | 命令执行通道，也是 MCP stdio 的承载通道 |
| Cua Driver | 目标机 | 现成（MIT） | `cua-driver serve` 在桌面会话里提供截图/输入；`cua-driver mcp --socket` 把它暴露为 stdio MCP |
| `tna-target.ps1` / `tna-target.sh` | 目标机 | 本项目 | 征得同意、安装/启用上面三样、写入受限的公钥、输出连接信息、status/revoke/uninstall |
| `tna.py` | 控制端 | 本项目 | 专用密钥、邀请命令（带 SHA256 校验）、独立 ssh_config 和 known_hosts、Codex 配置、诊断 |
| Codex | 控制端 | 用户自己安装 | 不在本项目里；通过 `codex mcp add` / `config.toml` 使用 |

## 数据流

接入（一次）：

1. 控制端 `tna init` 生成 `~/.tailnet-assist/id_ed25519`。
2. `tna invite --os <系统>` 打印一行命令：从本仓库固定 tag 下载目标端脚本 → 校验 SHA256 → 用公钥和有效期参数运行 `setup`。
3. 主人在桌面上运行，核对指纹，输入 YES。脚本依次：登录 Tailscale、启用 sshd、写公钥、装并启动 Cua Driver、输出 `TNA1:<base64url JSON>`（地址、用户名、主机公钥、cua-driver 路径、socket、到期时间）。
4. 控制端 `tna add TNA1:...`：严格校验每个字段（防止恶意连接信息往 ssh_config 里注入指令），写 `ssh_config`（`HostKeyAlias tna-<名>`、`StrictHostKeyChecking yes`、`IdentitiesOnly`、`BatchMode`、`ClearAllForwardings`）和固定的 `known_hosts`。

使用：

- 命令：`ssh -F ~/.tailnet-assist/ssh_config tna-<名> "<命令>"`。
- 界面：Codex 启动 `ssh -F … -T tna-<名> "<cua-driver> mcp --socket <本机 socket>"`，按 MCP stdio 协议通信。远端 `cua-driver mcp` 只是个转发进程，连到桌面会话里的 `cua-driver serve`。之所以要分成两个进程，是因为 SSH 会话本身没有桌面（Windows 上是另一个会话，Linux 上没有 DISPLAY/DBus），只有桌面会话里的进程能截屏和发送输入。

## 为什么不用 VPS / 反向隧道

之前的方案是两端都主动连华为云 VPS，由 VPS 上只监听 127.0.0.1 的反向端口中转。问题是 VPS 配置低、要自己维护 sshd 加固、端口要分配。Tailscale 把这些都交给现成组件：每台设备固定一个 100.x 地址，不需要端口分配；打洞失败时用 Tailscale 的公共中继。

代价：依赖 Tailscale 的协调服务（登录、密钥分发）；走 DERP 时延迟较高；两端都要装 Tailscale。不想依赖 Tailscale 公司可以自建 Headscale，但那又回到需要一台服务器。

## 为什么用 OpenSSH 而不是 Tailscale SSH

Tailscale SSH（`tailscale up --ssh`）的服务端只在 Linux 和 macOS 上可用，Windows 不支持。为了三个系统一套做法，统一用系统 OpenSSH + 密钥。Linux/macOS 上想用 Tailscale SSH 的可以自行替换，控制端的 MCP 启动命令不变。

## 威胁模型

| 风险 | 处理 |
|---|---|
| 局域网或公网上的人试登 sshd | 公钥行 `from=` 只认 Tailscale 地址段；Windows 新装的 sshd 防火墙只放行 Tailscale 地址段 |
| 控制端密钥泄露 | 密钥只在 Tailscale 内有效；默认 7 天自动失效；目标机 `revoke` 立即失效 |
| 利用 SSH 做跳板 | `restrict` 关掉端口转发、agent/X11 转发，只保留 pty |
| 中间人冒充目标机 | 主机公钥在 add 时固定；Tailscale 本身按设备密钥认证 |
| 下载的脚本被篡改 | 邀请命令指向固定 tag，并校验 SHA256 |
| 恶意的 `TNA1:` 连接信息 | 控制端对名称、用户、地址、公钥、路径、管道名逐项白名单校验，拒绝换行/引号/shell 元字符 |
| 屏幕操作越权 | Cua Driver 只能做桌面用户本来就能做的事；不绕过 macOS TCC 或 Windows 完整性级别 |
| 惄悄接入 | 脚本必须在桌面前交互运行（拒绝在 SSH 会话里安装 Cua），输入 YES；Tailscale、sshd 服务、自启动项都是系统里可见的正常组件 |

还需要知道的：Windows 上管理员账号的公钥只能放在 `administrators_authorized_keys`，它对本机所有管理员账号生效；控制端登录后的权限等同于该账号。只想让对方用普通权限，就在目标机上用一个标准用户账号登录桌面并运行脚本。
